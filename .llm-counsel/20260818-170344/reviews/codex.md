| R5-01 | valid | niche | P2 | The current read path still caps prose at 20,000 UTF-16 code units and collections at 200 while edits accept longer prose and replace complete collections. The JSON does disclose `truncated`, counts, and full-value digests, and the current guide warns that collection flags replace the complete set, so destructive loss requires an agent to ignore those signals on an unusually large project; this is a real footgun but not a large-share core-workflow break. |

The retry can therefore mismatch a landed write or post different options when the original did not land, but it requires the uncommon combination of an unconfirmed write and one of these optional flags. |

They can consume the CLI's 75-second budget under slow Linear/network conditions, but this is a degraded-network or unusually large-connection recovery-path reliability issue rather than a proven large-share break. |

## Residual

The maximum-size reference path remains latency-sensitive because member, team, and label resolution is sequential; production latency measurements would be needed to establish a useful supported cap or bounded-concurrency requirement.
