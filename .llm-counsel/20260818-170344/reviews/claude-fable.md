## Residual

- The `--flag=value` boolean hazard (R5-04) is CLI-wide and pre-existing: `--json=true`, `--force=true`, etc. all silently coerce to an ignored string. A single generic guard in `parseArgs` (reject a value when the flag is in `BOOLEAN_FLAGS`, mirroring `rejectValuedClearFlags`) would fix every current and future instance at once.
- R5-06's instruction text has drifted from the packet's quote — `:167` now says "escaped for your shell". Whoever authored that partial mitigation should reconcile it with the pre-supplied double quotes, which make correct escaping ambiguous; the file's own stdin mechanism (already used for `content` and the update body) is the clean fix for `--name`/`--description` too.
- No new P0/P1 observed at any TARGET, and none of the coordinator's dropped candidates warrant re-raising.
