## Residual

- **The `--flag=value`-on-a-boolean class is wider than R5-04's two flags.** `args.ts:110-113`
  applies to every entry in `BOOLEAN_FLAGS`, including the global `--json`. `orca ... --json=true`
  therefore emits human output at exit 0. This is pre-existing (not introduced by this diff) and it
  fails loudly for a JSON-parsing agent, so it is not a finding here — but a single generic
  "boolean flag takes no value" check in `parseArgs` would close R5-04 and this at once, and is
  cheaper than extending `rejectValuedClearFlags` flag by flag.
- **The missing-`signal` pattern in R5-03 is not confined to the four cited call sites.**
  `readLinearWriteLookup` (`orca-runtime.ts:37325-37331`) structurally cannot pass a signal — it
  takes a zero-arg thunk. Any future write-adjacent read added through it inherits the same gap.
  Changing the helper's shape to `(signal) => Promise<T>`, mirroring `runLinearAgentWrite`
  (`:37084-37085`), would make the omission impossible rather than merely fixed four times.
- **No new observation rises to P0/P1.** Per this seat's scope I did not scan the span for fresh
  release blockers.
